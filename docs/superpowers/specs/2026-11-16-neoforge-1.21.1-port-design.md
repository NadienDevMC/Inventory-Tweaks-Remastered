# Port de Inventory Tweaks a NeoForge 1.21.1 — Diseño

Fecha: 2026-11-16 · Estado: pendiente de revisión del usuario

## Objetivo

Portar Inventory Tweaks (Minecraft 1.12.2, Forge, coremod ASM, Java 8) a **NeoForge 1.21.1** con **Java 21**. Se mantiene el comportamiento del mod (ordenar inventario y cofres, auto-refill, atajos, GUI de ajustes) y se reemplaza todo lo que depende de APIs que ya no existen (ForgeGradle 2, coremods ASM, `GuiScreen`/`GuiButton`, canales de red Netty, `.lang`, `mcmod.info`).

**Criterio de éxito:** `./gradlew runClient` abre el juego con el mod cargado; en un mundo se puede ordenar el inventario (tecla R / clic medio), ordenar cofres con los 3 botones, usar los atajos, y abrir la pantalla de ajustes. Sin el mod en el servidor funciona igual (modo clics normales).

**Fuera de alcance:** reescribir la config como `ModConfigSpec`, cambiar la lógica de sorting más de lo necesario, nuevas funciones.

## Decisiones tomadas

| Tema | Decisión |
|---|---|
| Paquete base | `nadiendev.invtweaksremastered` (el usuario lo cambió desde el `invtweaks` original). La clase `@Mod` es `nadiendev.invtweaksremastered.InvTweaks`, **sola en la raíz**; el resto va en subpaquetes |
| `mod_id` | `inventorytweaks` (confirmado por el usuario; coincide con `assets/inventorytweaks/`) |
| Reemplazo del coremod ASM | Híbrido: detección en runtime como base, Mixins solo donde la heurística no alcance |
| CurseForge | Todavía no se publica: el paso de CurseForge queda configurado sin ID (se lee de `CURSEFORGE_PROJECT_ID`) |
| Versión inicial | `2.0.0` |
| Config | Se mantienen los archivos propios (reglas, árbol de ítems, `defaultconfig.dat`) en el directorio de config de NeoForge |

## Estructura de paquetes

Ya aplicada en el código fuente antes del port (los archivos sueltos de la raíz se movieron con `git mv` y se corrigieron `package`/imports):

Raíz: `src/main/java/nadiendev/invtweaksremastered/`

```
nadiendev/invtweaksremastered/
  InvTweaks.java          clase @Mod (única en la raíz); la lógica pasa a core/ durante el port
  api/                    API pública (+ api/container: anotaciones)
  config/                 InvTweaksConfig*, reglas de sorting
  container/              menús: managers, VanillaSlotMaps
  gui/                    InvTweaksGui* (pantallas y botones)
  handler/                sorting, atajos, auto-refill, ShortcutSpecification
  itemtree/               árbol de ítems
  util/                   InvTweaksConst, InvTweaksObfuscation
  integration/            ItemListChecker (detecta JEI con ModList; ItemListSorter se elimina)
  network/                payloads
  forge/                  proxies, ASM (se elimina durante el port)
```

Durante el port se añaden `core/` (lógica extraída de `InvTweaks.java`), `client/` (eventos y teclas) y `mixin/`. `forge/` desaparece.

## 1. Build y recursos

- `net.neoforged.gradle.userdev` + Gradle 8.11 (igual que MekanismMoreTiers). Java 21, Parchment 1.21.1, `neo_version=21.1.262`.
- `gradle.properties`: `mod_id=inventorytweaks`, `mod_group_id=nadiendev.invtweaksremastered`, `mod_name=InventoryTweaks`, `mod_version=2.0.0`, autores Jimeo Wan / Kobata (+ el port).
- Se **reescriben** `build.gradle`, `gradle.properties` y `settings.gradle` de la raíz: hoy son los de MekanismMoreTiers (Mekanism, Create, AE2, jarJar de la librería, etc.). No hay dependencia de JEI (ver más abajo). Se añade Mixin. `viejis gradles/` queda como referencia, sin tocarlo.
- Recursos:
  - `META-INF/neoforge.mods.toml` reemplaza a `mcmod.info` (la versión se inyecta por `processResources`).
  - `pack.mcmeta` con el `pack_format` de 1.21.1 (34).
  - Idiomas: los 27 `lang/*.lang` pasan a ser providers de datagen (`LanguageProvider`, una clase por idioma) y los `lang/*.json` se generan en `src/generated/resources` con `runData`.
  - `invtweaks.mixins.json` nuevo.
  - `invtweaks_at.cfg` (Access Transformer de 1.12) se elimina: NeoForge expone casi todo con getters. Solo se crea `META-INF/accesstransformer.cfg` si el compilador exige un campo concreto (`SlotWrapper.target`, `horse` del menú de caballo).
  - `InvTweaksConst` hoy recibe `@VERSION@` por reemplazo de ForgeGradle; pasa a leer la versión del `ModContainer`.
- CI: se adapta `.github/workflows/build.yml` (nombre del mod, relaciones de CurseForge: JEI opcional, sin checkout de la librería de Mekanism, JDK 21). Se crea `CHANGELOG.md`.

## 2. Reemplazo del coremod ASM

El coremod inyectaba en cada `Container` métodos `invtweaks$validInventory/validChest/largeChest/showButtons/rowSize/slotMap`. En NeoForge:

- **Detección en runtime** (`container/`): para un `AbstractContainerMenu`, los slots cuyo `Container` es el `Inventory` del jugador son inventario; el resto, cofre. Una tabla en `VanillaSlotMaps` (reescrita con las clases de menú de 1.21.1) cubre los menús vanilla.
- Las anotaciones `@ChestContainer`, `@InventoryContainer`, `@IgnoreContainer` y `ContainerSectionCallback` se leen **por reflexión**.
- Los menús de otros mods se resuelven con un JSON de compatibilidad (reemplaza a `CompatibilityConfigLoader`).
- **Mixins** solo para lo que la heurística no resuelva. Caso conocido: el foco de `EditBox` (antes ASM sobre `GuiTextField`) para desactivar el sort mientras se escribe.
- Se eliminan `forge/asm/*` y `FMLPlugin`.

## 3. Cliente

| Antes (1.12.2) | Ahora (NeoForge 1.21.1) |
|---|---|
| `ClientProxy.onTick` | `ClientTickEvent.Post` |
| `GuiScreenEvent` / botones en `initGui` | `ScreenEvent.Init.Post`, `KeyPressed`, `MouseButtonPressed` |
| `KeyBinding` + `ClientRegistry` | `KeyMapping` + `RegisterKeyMappingsEvent` |
| `PlayerEvent.ItemPickupEvent` | `ItemEntityPickupEvent.Post` |
| `GuiScreen`/`GuiButton`/`GuiContainer` | `Screen`/`AbstractWidget`/`AbstractContainerScreen` + `GuiGraphics` |
| `ModGuiFactory` | `IConfigScreenFactory` |
| `ToolTipEvent` | `ItemTooltipEvent` |

## 4. Red (soporte de servidor opcional)

- `ITPacketClick`, `ITPacketSortComplete`, `ITPacketLogin` pasan a `CustomPacketPayload` + `StreamCodec`, registrados con `RegisterPayloadHandlersEvent` (`optional()`).
- **Sin el mod en el servidor:** el cliente ordena con clics normales (`MultiPlayerGameMode.handleInventoryMouseClick`).
- **Con el mod en el servidor:** modo rápido con clics en lote, como el "server assist" actual.

## 5. Config y datos

- Se mantienen los archivos propios y se mueven al directorio de config de NeoForge (`FMLPaths.CONFIGDIR`).
- `itemtree.xml` se actualiza a los IDs de 1.21.1 (el "flattening" cambió los nombres de ítems). Es una de las partes más trabajosas.

## 6. Orden de trabajo

1. Gradle + esqueleto que compile y abra con `runClient`.
2. Árbol de ítems y config.
3. Detección de menús y sorting.
4. GUI, atajos y auto-refill.
5. Red.
6. Lang, changelog y CI.

Verificación: solo `./gradlew runClient` (sin servidores de prueba, GameTests ni autotests). Si hace falta alguna textura nueva, se hace al final, después del código, y se itera con el usuario hasta su OK.

## Desviaciones y reglas añadidas tras la revisión

- **JEI:** `ItemListSorter` engancha un comparador en la lista de JEI de 1.12. En el branch `1.21.1` de JEI el ordenado es el enum cerrado `IngredientSortStage` (clase interna, fuera de `mezz.jei.api`), sin hook para comparadores externos; se elimina `ItemListSorter` y queda solo `ItemListChecker` (JEI presente ⇒ la lista de ítems se considera visible para el layout de botones). No hay dependencia de compilación de JEI.
- **Archivos sin uso se borran** (decisión del usuario): `version.properties`, `mcmod.info`, `invtweaks_at.cfg`, los `.lang` y su `_README.txt`, `.travis.yml`, `invtweaks.keystore.enc`, `viejis gradles/`, todo `forge/` y `forge/asm/`, y el código muerto de texturas de botón. Se conservan los que sí se leen (`tree_readme.txt`, `defaultconfig.dat`, `itemtree.xml`, `invtweaks.png`).

## Riesgos conocidos

- El cambio de paquete a `nadiendev.invtweaksremastered` también rompe la API pública (`api/`, anotaciones `@ChestContainer`, etc.) para mods de terceros que dependieran de `invtweaks.api`. Se acepta: ningún mod de 1.12.2 puede cargar en 1.21.1.
- La reorganización de paquetes previa al port no se pudo compilar (el código sigue siendo 1.12.2 y el build de la raíz es el de otro mod). Se verificó por inspección: `package`/imports corregidos y `InvTweaks.compareItems(ItemStack, ItemStack, int, int)` hecho `public` porque `handler/InvTweaksHandlerSorting` lo llama desde otro paquete. Puede haber más accesos *package-private* en clases internas; saldrán en la primera compilación del port.
- El volumen de código a reescribir es alto (~9.5k líneas); la parte de GUI y los IDs del árbol de ítems concentran la mayor parte del trabajo.
